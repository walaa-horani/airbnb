Section 3 of 5 — Booking & Payment Lifecycle

End-to-end flow from date selection to host payout (and refund path)

Phase 1 — Guest Books

1
Guest selects dates + guests Convex
Calendar blocks unavailable dates by querying confirmed bookings. Smart picker prevents check-in on checkout day of existing booking.
2
Cost breakdown calculated
Nightly rate × nights$X
Cleaning fee$X
Service fee (5% platform)$X
Total charged to guest$X
Host receives (after fee)$X
3
Guest chooses payment method
Stripe card (default) or PayPal. Host must have that payment method connected — if not, only available option is shown.

Phase 2 — Payment Processing (splits by method)

Stripe Connect Path

4a
Payment Intent created Stripe
Convex action creates PaymentIntent with application_fee_amount (5%) and transfer_data.destination = host's Stripe account.
5a
Stripe webhook fires StripeConvex
payment_intent.succeeded → booking status → confirmed. Fee auto-split handled by Stripe.

PayPal Marketplace Path

4b
Order created PayPal
Convex action creates Order via Orders API v2 with purchase_units including platform fee and payee = host's PayPal merchant ID.
5b
PayPal webhook fires PayPalConvex
PAYMENT.CAPTURE.COMPLETED → booking status → confirmed.

Phase 3 — Confirmation & Completion

6
Emails sent Resend
Guest gets booking confirmation. Host gets new booking alert. Both include full details, dates, amounts.
7
Booking completes automatically Convex Cron
Scheduled job runs at midnight after checkout date. Status → completed. Guest can now leave a review.

Cancellation & Refund Path

R1
Guest or host cancels Convex
Booking status → cancelled. Records who cancelled and reason.
R2
Refund triggered automatically
Stripe: refunds.create on the PaymentIntent. PayPal: capture.refund on the capture ID. Full refund issued immediately.
R3
Cancellation emails sent Resend
Both guest and host notified with refund details and timeline.
